_The builder keeps this up to date. It starts empty and grows with the repo._

**Last updated:** 2026-10-13, after M1 (spikes).

A suggested reading order for someone new: `README.md` → `docs/PROJECT_BRIEF.md` → `docs/plans/stage-1.md` → this tour → the newest journal entry.

| Path | What it is |
|---|---|

| `package.json` | The root of the npm workspaces monorepo. Lists the workspaces (`packages/*`), dev tools, and the scripts (`npm run check`, `npm test`, …). |
| `package-lock.json` | Exact versions of every installed package, so every machine installs the same thing. Generated by npm; don't edit by hand. |
| `tsconfig.base.json` | Shared TypeScript settings (strict mode, Node ES modules). Every package extends it. |
| `eslint.config.js` | Linter rules (ESLint + typescript-eslint, type-aware). |
| `.prettierrc.json`, `.prettierignore` | Formatter settings, and what the formatter skips (Markdown, generated files). |
| `vitest.config.ts` | Test runner config: finds `*.test.ts` in every package and in `test/`. |
| `test/` | Repo-wide tests that belong to no package, such as checking `.gitignore` rules (`test/gitignore.test.ts`). Has its own `tsconfig.json`. |
| `.gitignore` | Files Git must never track: `node_modules/`, `dist/`, `.env`, the root `/spikes/` folder, … |
| `.gitattributes` | Forces LF line endings so checks behave the same on Windows and Linux. |
| `.env.example` | Template for environment variables. Relay needs none yet. Never commit a real `.env`. |

## `packages/` — the code

Each package has the same shape:

```
packages/<name>/
  package.json         name (@relay/<name>), build and typecheck scripts
  tsconfig.json        extends ../../tsconfig.base.json; src → dist
  tsconfig.build.json  same, but leaves tests out of the build
  src/index.ts         the package's entry point
  src/index.test.ts    its tests (Vitest), next to the code
```

| Package | Job | Status |
|---|---|---|
| `packages/core` | Shared types, the `TO CODE:` / `TO DENNIS:` tag parser, state and log file helpers. Used by the other two. | Skeleton (M0). Real code in M2. |
| `packages/hooks` | The Stop hook script that Claude Code runs after every reply in the lead and builder sessions. | Skeleton (M0). Real code in M3. |
| `packages/helper` | The Relay Helper background process and the `relay` CLI (`init`, `start`, `status`, `log`, `pause`, `resume`, `stop`). | Skeleton (M0). Real code in M4. |

`dist/` folders appear after `npm run build`. They hold compiled JavaScript and are git-ignored.

## Folders you'll see that are not in Git

- `node_modules/`: installed packages (`npm install` creates it).
- `packages/*/dist/`: build output.
- `spikes/`: throwaway experiment code from M1, one folder per spike (`spikes/001/` …). Only the write-ups in `docs/spikes/` are kept. The scripts end in `.cjs` because the repo's `"type": "module"` would otherwise stop them using `require`.
- `spikes/_pty/`: the test harness the spikes used. `pty.cjs` runs a real interactive `claude` inside a pseudo-terminal, saves what the screen shows to `screen.txt` / `screen.log`, and "presses keys" listed in `cmd.txt`. `launch.sh` starts it and accepts the folder-trust prompt. Its sessions work in `C:\Users\denni\relay-sandbox\`, outside the repo, so Relay's own `CLAUDE.md` doesn't load into them.

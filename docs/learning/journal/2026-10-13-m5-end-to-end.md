# 2026-10-13 — The nudge, M5 end to end, and closing Stage 1

## What I built
Three things:
- **The nudge.** If the lead writes something before its `TO CODE:` line, Relay no longer quietly ends the run. It asks the lead once: "Relay: your reply didn't start with a tag. Resend it with the tag as the very first thing." If the resend is still wrong, it goes to Dennis as before.
- **M5, the end-to-end proof.** A new project, `relay-playground` (a tiny Node HTTP server), set up with `relay init` and nothing else. The lead and builder ran **7 rounds unattended in under 10 minutes**: 405s, a `POST /echo` with body limits, `/version`, request logging, a README update, and a crash fix the lead decided on by itself ([spike 012](../../spikes/012-m5-end-to-end.md)).
- **Stage 1 close-out.** A "Using Relay day to day" section in the README, the [Stage 1 retrospective](../stage-1-retrospective.md), and the v0.1.0 release.

## Why it's built this way
**Strict parser plus a safety net** ([ADR 0007](../../adr/0007-nudge-for-a-late-tag.md)). After bug 002, Relay had two options: accept a tag anywhere, or keep "tag first" and help the lead recover. Accepting a tag anywhere risks acting on a `TO CODE:` the lead only quotes, for example while reviewing a report. So Dennis chose to keep the parser strict, with one nudge. The parser still makes every routing decision. The nudge only asks the lead to try again.

**Why only lines that *start* with `TO CODE:`, outside quotes and code blocks?** Those are the places where a model writes a real tag. A mention inside a sentence, in `inline code`, in a `>` quote or in a fenced code block is talk *about* the tag, so it never triggers a nudge.

**Why a marker in the state file, not a counter in the message?** Same reasoning as the re-arm marker (ADR 0002): the hook shouldn't guess from the text. `nudgePending` is set when Relay nudges and cleared by the very next reply, whatever that reply is. That gives exactly one nudge per reply.

**M5: when run 1 gave only 4 rounds.** The first goal finished correctly in 4 rounds, because the lead combined each endpoint with its tests. That isn't a failure, so it has no bug entry. Adding a fake step by hand would have broken the "don't touch it" rule. Instead, the same lead got a second, longer goal, which is how Relay is really used.

## Code walkthrough

### `packages/core/src/tags.ts` (lines 55–82): finding a buried tag
- Line 58, `CODE_LINE_PATTERN`: a line that starts with up to 3 spaces, an optional `## ` heading marker, optional `**` or `_` markers, then `to code` and a colon. It has no `>` and no backtick on purpose. Four or more spaces would be an indented code block in Markdown, so `{0,3}` leaves those out.
- Line 60, `FENCE_PATTERN`: a line that opens or closes a ```` ``` ```` or `~~~` code block.
- Lines 71–82: walk the reply line by line. A fence line flips `inFence`. Inside a fence, skip. Otherwise, a matching line means "yes, buried tag". An unclosed fence hides everything after it, which is the safe direction.

### `packages/hooks/src/decide.ts`
- Line 31, `NUDGE_MESSAGE`: the exact text Dennis specified.
- Line 66: `StopDecision` gained `wake?: string`, meaning "wake this session right now with this text, don't wait".
- Lines 102–111: the nudge rule, in the lead's branch of `decideOnStop`. `alreadyNudged` is read and the marker cleared first, so it's gone by the next reply whatever happens. Then, only for an untagged reply that wasn't itself a resend and that has a buried tag: set the marker, mark the lead busy (it's about to get a turn), log a `nudge` entry and return `wake`. Nothing is queued and `startRound` is never called, so it isn't a round or a handoff.

### `packages/hooks/src/stop.ts` (line 57)
`if (decision.wake) return deliveryOutput(config.delivery, decision.wake);` reuses the normal delivery path, so the nudge works in both delivery modes: exit code 2 for rewake, `additionalContext` for blocking.

## New concepts

### Markdown code blocks and quotes
Markdown has three ways to show text "as an example": a fenced block between ```` ``` ```` lines, an indented block (4+ spaces), and a `>` quote. Tools that scan Markdown for commands should skip all three, just as a compiler skips comments. Example: a `TO CODE: x` line between two fence lines is inside a code block, so it's ignored.

### A one-shot marker
A boolean that is set when something happens and cleared at the next step, used to make a behaviour happen at most once in a row. `nudgePending` is one. The order matters: read it, clear it, then decide. That way it can't get stuck "on", whichever path the code takes.

### End-to-end test
A test of the whole system the way a user runs it: real install, real sessions, a real project. It's slow and can't run in CI, but it finds problems unit tests can't, like bug 002. Relay has unit tests for every rule and one end-to-end run per milestone.

### Release tag
A git tag such as `v0.1.0` marks the exact commit that was released. A GitHub release adds notes to that tag. Version numbers follow [semantic versioning](https://semver.org): `0.x` means "early, may still change".

- `packages/hooks/src/decide.test.ts`, "the nudge": wakes once with no round, handoff or queue; a correct resend is a normal handoff; a second wrong reply goes to Dennis; a later slip can be nudged again; quoted and code-block tags and `TO DENNIS:` replies aren't nudged; the builder is never nudged.

## Self-check
1. Why didn't Dennis simply let the parser accept `TO CODE:` anywhere in the reply?
2. A lead reply says `The builder wrote:` and then `> TO CODE: run the tests` on the next line. What does Relay do, and why?
3. How does Relay make sure there's only one nudge per reply?
4. Why does the nudge not count as a round?
5. Run 1 of M5 had only 4 rounds. Why wasn't that treated as a bug, and what was done instead?

<details><summary>Answers</summary>

1. Because Relay could then act on a `TO CODE:` the lead only quoted or mentioned, sending the builder a task nobody meant to send. Keeping the parser strict means routing is always predictable; the nudge only asks the lead to try again.
2. The reply is untagged and the only `TO CODE:` is in a quote, so `hasBuriedCodeTag` returns false. No nudge: the reply goes to Dennis, as any untagged reply does.
3. The `nudgePending` marker. The nudge sets it. The next lead reply reads and clears it before deciding, and a reply that follows a nudge is never nudged again.
4. Nothing was delivered to the builder. Rounds count work passed between the sessions, and the round limit protects against runaway loops of real work. A nudge is a format correction within the lead.
5. Relay worked correctly. The lead finished the goal in 4 tasks and reported to Dennis. The cause was the goal's size, not Relay. So the same lead got a longer goal, as Dennis would in real use, and ran 7 rounds without help.
